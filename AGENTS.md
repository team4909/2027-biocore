# AGENTS.md

WPILib 2026 Java robot for FRC team 4909. The repo is named "2027-biocore", but `build.gradle`, `settings.gradle`, and `.wpilib/wpilib_preferences.json` all target the 2026 season (GradleRIO 2026.2.1, Java 17). Stack: CTRE Phoenix 6 swerve + PathPlanner. No README and no CI exist; verify changes with a local build.

## Commands

- `./gradlew compileJava` — fastest compile check.
- `./gradlew build` — compile + tests. `src/test` does not exist yet, so this is the whole verification. New tests go in `src/test/java`; JUnit 5 is configured (`useJUnitPlatform`, extension autodetection on).
- `./gradlew simulateJava` — desktop simulation. Sim GUI and simulated DS are enabled by default in `build.gradle`.
- `./gradlew deploy -PteamNumber=4909` — deploy to the team's roboRIO. `deploy` reads the team number from `.wpilib/wpilib_preferences.json`, which is currently the placeholder `9999` (git history shows it was `4909`); `-PteamNumber` overrides it without editing tracked files.
- No linter/formatter is configured. Match the file you are editing (4-space indent in `RobotContainer`/`Telemetry`, 2-space in template files).

## Code map

- `frc.robot.Main` → `Robot` → `RobotContainer`. `Robot` is a plain `TimedRobot` (not AdvantageKit `LoggedRobot`) and runs `CommandScheduler` itself in `robotPeriodic()`.
- `RobotContainer` is the wiring hub: Xbox controller port 0, drivetrain default command, SysId bindings (back/start + y/x), brake/point-wheel bindings, PathPlanner `AutoBuilder`, and SmartDashboard choosers "Auto Mode" and "Manual Mirror Override".
- `subsystems/CommandSwerveDrivetrain` extends the CTRE-generated `TunerSwerveDrivetrain`. `generated/TunerConstants` is generated by the Tuner X 2026 Swerve Project Generator — regenerating it overwrites hand edits. The PathPlanner-only helpers `getRobotRelativeSpeeds()` and `resetPose()` live in `CommandSwerveDrivetrain` and must survive regeneration because `RobotContainer` calls them.
- Hardware config all lives in `generated/TunerConstants`: `CANivore2` bus, Pigeon 2 ID 0, TalonFX/CANcoder IDs, encoder offsets, `kInvertLeftSide`/`kInvertRightSide`. If the robot builds and sims but drives wrong on real hardware, check these instead of command logic.
- `commands/Autos`, `ExampleCommand`, `ExampleSubsystem`, and `Constants` are unused WPILib template leftovers. Autonomous selection is PathPlanner-only via `AutoBuilder.buildAutoChooser()`.

## PathPlanner

- Autos, paths, `navgrid.json`, and `settings.json` live under `src/main/deploy/pathplanner/` and are deployed to `/home/lvuser/deploy`. Edit them in the PathPlanner GUI, not by hand.
- `RobotConfig.fromGUISettings()` reads `deploy/pathplanner/settings.json`; if it is missing or malformed, `configureAutoBuilder()` only reports an error and autos stay unusable. Keep that file in sync with robot geometry.
- Register named commands in `RobotContainer.configureNamedCommands()` before `configureAutoBuilder()` runs.
- Alliance mirroring is manual, not automatic: the `shouldFlipPath` supplier is the SmartDashboard "Manual Mirror Override" chooser, defaulting to "Don't Mirror (Blue)". Autos do not flip for red alliance unless that option is selected.
- `frcStaticFileDeploy` uses `deleteOldFiles = false`, so renamed/removed deploy assets linger on the roboRIO.
- `RobotContainer.driveRobotRelative()` applies PathPlanner's robot-relative `ChassisSpeeds` through `robotCentricDrive` (`SwerveRequest.RobotCentric`, zeroed deadbands) — don't confuse it with the operator's `SwerveRequest.FieldCentric` `drive` request.
- `RobotContainer.driveRobotRelative()` feeds PathPlanner's robot-relative speeds into a `SwerveRequest.FieldCentric` (which interprets them as field-relative). If autos track poorly whenever the robot has nonzero heading, replace it with `SwerveRequest.ApplyRobotSpeeds`.

## Simulation and logs

- `Telemetry` calls `SignalLogger.start()` when constructed; `Robot` uses Phoenix 6 `HootAutoReplay` for timestamp/joystick replay. Hoot logs land in `logs/` and CTRE sim device state in `ctre_sim/`; both are gitignored — never commit them.
- Vendordeps include PhotonLib, ChoreoLib, and AdvantageKit, but no code uses them yet (no vision pipeline, no Choreo trajectories, no AK logging). Do not assume those integrations exist.
